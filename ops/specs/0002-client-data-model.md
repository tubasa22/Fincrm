## `client_key` 생성 규칙

세 소스의 이름 표기가 다릅니다. 커미션 명세는 `LEE,MAL H`,
FinCRM은 한글일 수 있고, P&C는 `EIZEN LLC DBA EIZEN SUSHI & SAKE BAR` 같은 법인명입니다.

제안 (Codex가 실제 데이터 보고 확정):

- **개인** — `성(영문 대문자)` + `이름 첫 단어` + `생년월일 YYYYMMDD`
  예: `LEE-MAL-19450312`
- **생년월일이 없는 소스**(커미션 명세) — `성` + `이름` + `전화 뒤 4자리`.
  둘 다 없으면 임시키를 발급하고 `match: review`
- **법인** — 정규화한 법인명 (DBA·INC·LLC 제거, 공백→하이픈, 대문자)
  예: `EIZEN` / `R-J-MEDSPA`

### 자동 매칭 결과를 그대로 병합하지 마세요

| 값 | 뜻 |
|---|---|
| `confirmed` | 사람이 확인함. 기준값 |
| `auto` | 규칙으로 맞춤. 쓰되 되돌릴 수 있게 원본 유지 |
| `review` | 애매함. **병합하지 말고** 목록으로 남겨 Jaden이 화면에서 고르게 |

동명이인이 실재합니다 — 커미션 명세에 `KIM,YOUNG` 과 `KIM,YOUNG OK` 가 따로 있습니다.
틀린 병합은 되돌리기 어렵습니다. 의심되면 `review`.
